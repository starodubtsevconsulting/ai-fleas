# Personal Governor method: Monthly plan-reality reconciliation — v1

## Purpose

Maintain a stable monthly planning baseline, a living current plan, and an evidence-based view of what actually happened so the Governor can distinguish deliberate adaptation from unnoticed drift.

The method closes the loop between strategy, calendar allocation, execution evidence, and future planning without rewriting history to make the plan appear successful.

## Core model

Maintain three distinct monthly states:

1. **Baseline plan** — the human-approved snapshot of intended priorities, outcomes, constraints, and approximate allocation at the start of the month. Once accepted, preserve it unchanged.
2. **Current plan** — the Governor's living operational interpretation of the month. It may change as evidence, commitments, opportunities, or capacity change.
3. **Actual** — what materially happened, supported by authorized evidence such as calendar history, task-tracker state, completed deliverables, workflow activity, publications, direct human report, or relevant external outcomes.

Do not overwrite the baseline when the current plan changes.

## Start-of-month procedure

Create the baseline before discretionary monthly allocation expands.

Capture only what is useful:
- active human-owned goals and current strategy;
- a small set of intended monthly outcomes/checkpoints;
- known fixed commitments and deadlines;
- expected capacity constraints or protected recovery boundaries;
- approximate allocation where useful;
- deliberate non-goals or deferred work.

Record the baseline in durable Governor memory. The calendar remains the operational commitment surface; the baseline is not a duplicate calendar.

## Planning traceability

Monthly outcomes are the bridge between durable strategy and operational allocation.

Where configured structure exists, preserve a recoverable lineage:

```text
human-owned goal -> strategy/stage -> monthly outcome -> profile -> workflow -> project
```

Daily activity/calendar allocation then extends that lineage to execution. Material actual evidence should be attributable back through the same structure at reconciliation time.

A monthly plan should not contain orphan discretionary outcomes that cannot explain which goal/strategy they serve. Necessary commitments/constraints are valid without goal advancement, but their capacity cost should be explicit.

## During-the-month procedure

Use the daily planning sync and normal calendar reconciliation to execute the current plan.

When a material change occurs:
- preserve the baseline;
- update the current plan;
- record what changed;
- record the evidence or human decision that justified the change;
- state what was displaced, reduced, added, or deferred;
- record the next reassessment boundary when useful.

Minor calendar movement does not require a monthly-plan change record. Record only changes that materially affect intended outcomes, allocation, or strategy.

## End-of-month reconciliation

Compare **baseline -> current plan -> actual**.

For each meaningful intended outcome, determine:
- achieved;
- partially achieved;
- unchanged;
- invalidated by new evidence;
- deliberately abandoned;
- displaced.

For material deviations, classify the best-supported reason without inventing motives. Useful classes include:
- deliberate reprioritization;
- external constraint or dependency;
- new evidence/discovery/opportunity;
- capacity/recovery constraint;
- planning error or unrealistic allocation;
- execution drift or repeated displacement;
- unexplained/insufficient evidence.

When the cause is uncertain, keep it uncertain and ask the human if the distinction matters.

## Deviation analysis

Do not score the human or treat deviation itself as failure.

Ask:
- Did the deviation improve alignment with active goals?
- Was it consciously chosen or did it emerge accidentally?
- What did it displace?
- Did the same kind of displacement repeat?
- Was the original plan wrong, or was execution inconsistent with a still-valid plan?
- Did calendar changes predict actual behavior?
- Which constraints should change next month?

Aligned work is not automatically justified if it repeatedly displaces a higher-priority chosen outcome.

## Reporting hierarchy

When the governed-human profile exposes workflow/project structure, mirror that structure in the month report instead of inventing a separate reporting taxonomy.

Resolve:

```text
governed human
  -> profile
    -> configured workflow
      -> configured project
        -> material monthly activities
          -> evidence
          -> result / consequence
          -> contribution to human-owned goals
```

Only include workflows/projects with material activity, commitments, or meaningful displacement during the month. A project may appear under more than one workflow when the profile binds it that way; attribute each activity to the workflow through which it occurred.

For every active project, capture:
- intended outcome and related goal;
- material activity timeline (what happened, when, how, and evidence);
- planned vs unplanned status;
- result/consequence;
- material plan changes and what they displaced;
- project movement: closer, unchanged, farther, invalidated, or unknown;
- allocation deviation: under, approximately intended, over, or unknown;
- next-month implication.

Then roll up:
- project -> workflow movement;
- workflow -> profile movement;
- profile -> governed-human goal movement;
- cross-workflow/project displacement competing for the same human capacity.

## Output

A useful month-end review should normally produce:
- executive goal-alignment summary;
- active profile/workflow/project hierarchy for the month;
- original baseline outcomes;
- material activity timeline per active project;
- major in-month plan changes and reasons;
- actual material outcomes/evidence;
- deviations, displacement, and classifications;
- explicit closer/unchanged/farther movement toward human-owned goals;
- recurring patterns worth carrying forward;
- what should stop, continue, or change;
- a small set of candidate checkpoint outcomes for the next month.

The next month's baseline should be created from this review plus current strategy, not by blindly carrying unfinished work forward.

## Relationship to daily and weekly planning

Daily planning answers: **what matters today and how should the calendar reflect it?**

Weekly review answers: **is the current allocation still working?**

Monthly reconciliation answers: **what did we intend, how did the plan change, what actually happened, why did we deviate, and what should change next month?**

The monthly method should consume evidence produced by daily/weekly governance rather than reconstructing the month from memory alone.

## Evidence and system boundaries

Use the smallest useful evidence set. Prefer:
- calendar history for actual time commitments and movement;
- task tracker for operational state;
- workflow/project artifacts for completed outputs;
- permanent memory for decisions and plan-change rationale;
- direct human report where evidence cannot explain why.

Do not turn the calendar into a task database or permanent memory into a duplicate calendar.

## Anti-patterns

Avoid:
- editing the baseline to match reality;
- measuring success only by task count or hours;
- treating every unplanned useful activity as success;
- treating every deviation as failure;
- inventing motives for missed work;
- carrying all unfinished work into the next month;
- creating a detailed monthly plan that crowds out execution.
