# Admin-delegated release approval

An author may explicitly appoint the initialized Writing Admin to make the release decision for an exact article and destination. This is an alternative decision path when the author does not plan to listen or review personally. It is not evidence that the author listened.

Admin records a durable `release-delegation` receipt under `.agent-runtime/writing/delegations/`. The receipt names the direct human instruction, authorizing task, profile and workflow, article revision, saved destination, allowed action (`schedule` or another exact action), publication target, and any limits. A broad standing instruction does not silently cover another article or immediate publication. Admin checks the final article, selected visuals, source claims, destination rendering, and archived narration script/audio as the author's representative. Admin records its own verdict and remaining defects. It never writes `human-listen` evidence or says the author listened.

Reviewer independently verifies the receipt's origin and exact scope, the final review and destination evidence, the three-surface mirror, and Admin's recorded verdict. If anything is stale or unresolved, return Writer-owned `changes_required` or a precise human/action blocker. If all checks pass while the run is at `human_review`, return `admin_delegated` with the exact `review`, `destination-review`, and `release-delegation` references. This event substitutes a delegated release decision for the author's listen-through confirmation; it does not substitute for independent review or prove any playback.

Release Coordinator accepts `admin_delegated` only for the exact revision, destination, action, and target in the verified receipt. It records the release as **Admin-delegated; author listening unconfirmed**. A material change after the receipt requires a new Admin verdict and independent review. The narration remains in the permanent article archive and outside Git.
