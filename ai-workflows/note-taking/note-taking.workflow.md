# Note-taking workflow

Use this workflow only for explicitly requested capture, organization, review, retrieval, or development of user-owned
notes. Preserve the source and its meaning before classifying, summarizing, linking, or promoting it.

## Purpose

Maintain an evolving note system with low-friction capture, deliberate organization, reliable retrieval, and periodic
conversion of accumulated notes into knowledge or action.

## Strategy selection

Choose, combine, or adapt the relevant guide instead of forcing every note into one taxonomy:

- [Cornell](guides/cornell.md) for structured learning and recall;
- [custom capture](guides/custom-capture.md) for capture-first personal systems;
- [PARA](guides/para.md) for organization by actionability and context;
- [Zettelkasten](guides/zettelkasten.md) for developing connected ideas.

The active profile may provide private storage locations and conventions. A host supplies the mechanics for reading,
writing, indexing, or searching notes; this workflow does not select an application, database, model, or transport.

## Required behavior

- Preserve the original note and source before applying transformations.
- Treat notes and files as authoritative user artifacts.
- Treat generated summaries, classifications, links, indexes, embeddings, and metadata as replaceable derivations.
- Do not silently mutate authoritative notes based on derived data.
- Keep execution context temporary unless the selected profile explicitly defines an allowed durable knowledge record.
- Ask before resolving an ambiguous classification when the choice would materially affect retrieval or meaning.

## Typical flow

`capture -> preserve source -> apply the selected strategy -> connect or classify -> review -> retrieve or use`

Meaningful events include a note being captured, a source being attached, a connection being discovered, a review
becoming due, a note being distilled, an action implication being found, a retrieval request, or an archive decision.
