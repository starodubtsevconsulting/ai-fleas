# Fictional source extraction and contextual verification

The example human profile owns the [challenge sources and references](../../../ai-profile/example/data/financial-insights-challenges/README.md). This pipeline consumes that dataset without applying records or changing operational profiles.

Run two separately measured tasks with selected native-image test profiles: blind extraction from each original page (six fresh requests), then mechanical preparation of five documents followed by JSON-aware verification of every original page (five fresh requests). Mechanical failures remain actual failures with unavailable candidates; they never become fabricated JSON. No source reference answers, support annotations, transcripts, diagnostic document IDs or case filenames enter model context.

An observation must distinguish printed facts, contextual inference, ambiguity and unavailable source evidence. Missing printed currency remains unknown even when a mechanical candidate infers CAD. A conflicting printed total remains the printed number alongside the separately calculated component sum, with ambiguity reported. Page-only extraction does not score classifications requiring joint evidence from multiple pages. Whole-document verification requires all original pages, actual native image payload counts and page-specific literal evidence.

Transport failures stop the arm without retries. Accuracy failures with valid transport remain measured observations. Preserve raw logs privately, source and prompt hashes, actual usage where available and separately measured mechanical, visual and full pipeline time. Native harness context differences prevent causal overhead claims. No inference starts until the current baseline comparison finishes and Admin authorizes execution.

Score and report denominators separately: page extraction counts requested printed financial facts and single-page contextual classifications, including expected unknown observations on the other page. Joint multi-page semantic classifications are excluded from that denominator and included once in whole-document checks. Never pool these tasks as independent repeated observations. Mechanical non-support/read failure is a separate preparation outcome, not a visual accuracy failure; its empty actual candidate can still receive a grounded contextual visual assessment.

Before full execution, run a separately labelled two-page pilot for each harness. The pilot prepares only that original document and performs one whole-document request, with no blind page requests. It cannot count as the complete challenge suite. Native hooks must prove two image payloads before full-suite readiness is claimed. Check-plan resolves the selected configuration and verifies fictional source hashes without starting a harness or creating a run directory.

Reference audits may correct demonstrated annotation errors only through a labelled amendment after execution finishes. Preserve original answers, run JSON bytes, original scores and executed reference/evaluator hashes. Publish old/new reference hashes, exact field corrections and separately recomputed scores from the same stored answers; never rerun inference or overwrite historical evidence to hide an amendment. Distinguish raw financial observations, canonical semantic mapping and strict literal support/evidence/status. A correction to whether a provider status is printed changes support scoring, not the observed value, source document or model answer.
