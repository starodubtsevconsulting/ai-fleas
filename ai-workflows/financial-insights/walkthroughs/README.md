## Tool and evidence conventions

Example paths are relative to an already authorized reports root mapped as `<year>/<business>/<quarter>/{in,out,statements}`. Discover the actual mapping first; capitalization and organization levels can differ. `list`, `search`, `read-json`, `extract`, `inspect-page`, and `calculate` below describe operations, not guaranteed command names. Resolve the profile-authorized tool for each operation. Never invent an executable or silently broaden access.

Bound each operation: list one mapped section at a time, search one period/business at a time, return matching filenames or selected JSON fields rather than whole trees, extract a small page batch, then continue from a recorded checkpoint. A full-coverage claim requires finishing every relevant batch. Missing JSON does not remove a source PDF from the inventory. For a read-only question, derived extraction can remain in memory or permitted runtime evidence; publishing or correcting adjacent CSV/JSON is a separate governed mutation. For authorized intake, normalize and validate extraction beside its source before reporting intake complete. Preserve actual schemas and existing `.pdf.json` naming; normalization and extraction are separate states, and uncertain OCR fields remain review-pending.

For example, an operational recipe is: list at most 20 paths from one mapped `out` folder and retain the next-page cursor; pair each PDF with an existing sidecar; parse at most 10 sidecars per call into selected facts using their actual schema; return only candidate rows and parse failures; extract pages 1–3 of one missing/conflicting source; continue remaining pages if the document is longer. For statements, iterate every transaction-page batch and retain coverage rather than searching only known vendor names. These are suggested batch sizes; a tighter normative flow or host limit wins. Adjust within those limits for the selected tool and document size; they are not a license to stop after the first batch.

Track actual operations and decisions in memory or permitted visible runtime checkpoints; this table is an execution trace, not a required durable action-log file. Keep lasting cross-source conclusions in the one quarter summary when authorized. Fictional steps below have no measured elapsed times.

Text extraction is not vision; claim visual checking only after inspecting the supplied source pages. If a tool fails, record the failure, narrow or use an authorized alternative, and continue supported work. Never turn a failed inspection into zero spending or proven nonpayment.
