# Bounded exploration and implementation

Use for a port or repair where transitive dependencies are not fully known. Give Coder a goal-shaped outcome, allowed
write and read-only roots, useful entry points, existing behavior to preserve, explicit exclusions, and acceptance
evidence. Coder may trace related code within the read scope, choose the necessary files within the write scope, and
make several local revisions before its single report. Do not turn the starting-file list into a complete-file mandate.

Keep the stage small enough to review and complete within the transport's verified run limit. If the implementation
needs another write root, different behavior, or an independent gate, Coder stops and reports the exact need. If a
transport disconnects, Admin checks the remote task and checkout before sending a new packet.
