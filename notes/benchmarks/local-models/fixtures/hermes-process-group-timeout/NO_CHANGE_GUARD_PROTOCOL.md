# Live no-change patch guard comparison

Question: can a supervisor stop a local Coder's confirmed no-change patch loop sooner **without reducing accepted source-port work**?

Use the frozen process-group [starter](starter/run-installer-with-timeout.py), the [reviewed reference](reference/run-installer-with-timeout.py) copied byte for byte from the earlier accepted algorithm run, and the same focused source-port assignment in both arms. The assignment asks Coder to make the staged target match the reviewed source, then stop and report. Keep Qwen3-Coder-Next Q5_K_M, the existing Hermes profile, CLI `chat -Q` route, 20-turn cap, exact staged-file write root, 180-second run deadline, and six-case [independent verifier](verify.py) fixed. Coder may read the task, target, and reviewed source; it may edit only the target. Admin runs the verifier and checks byte equality, scope, process stop, and source after the Coder process exits. The production helper and Hermes runtime are read-only.

- **A, ordinary run:** existing configured delegate and deadline, with no additional intervention.
- **B, experimental watchdog:** same delegate and assignment. A read-only observer polls this Coder profile's session store for the run identified by its exact staged target path. Count only consecutive `patch` tool results with `success: true` and `no_change: true` for that same path. Any other tool call, failed result, or different path resets the count. After the third result, terminate the *launched delegate process group* with SIGTERM, wait up to five seconds, then attempt SIGKILL on that group and reap the launcher. Do not edit the candidate. The watchdog does not alter Hermes config or tool results.

Run eight fresh starts per arm in the fixed order **ABBA, BAAB, ABBA, BAAB**, restoring the same starter for every staged target. Freeze both prompts and the watchdog threshold before the first run; do not tune them after failures. Verify that the observer sees live session messages during a pilot; if it does not, stop the comparison and report that transport limit rather than claim an inactive guard was tested.

Record accepted code (six-case verifier, byte match to reviewed source, scope), completed handoff (normal Coder exit plus report), wall time, model calls/output tokens, patch calls, confirmed no-change patches, guard trigger and stop, timeout, other scope errors, and compaction. Treat guard-terminated accepted code separately from a completed Coder handoff. A run that simply finishes faster with incorrect code is a failure. Compare accepted work per Coder minute only after the interleaved batch; report the trigger rate and uncertainty. This is a staged supervisor test, not proof that an in-process Hermes guard would behave identically.
