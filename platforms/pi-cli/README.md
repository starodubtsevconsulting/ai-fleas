# Pi CLI adapter

`pi-cli` is the AI Fleas platform ID for the Pi terminal harness. The selected work profile still owns workflow and project authorization, model bindings, and platform selection. Pi's `PI_CODING_AGENT_DIR` names a directory of harness configuration; its JSON files are not another work profile and do not establish an agent identity.

| Portable concept | Pi CLI realization |
| --- | --- |
| Logical agent | One role in the selected workflow roster, currently prepared only for Dev Coder |
| Runtime configuration | A project and role specific `PI_CODING_AGENT_DIR` generated by `pi-agents prepare` |
| Agent instance | One Pi conversation/session started with that directory and the authorized project as working directory |
| Instance ID | Pi's exact, immutable session ID; the directory path and session file name are not substitutes |
| Runtime scope | Exact work profile, workflow, logical project, and authorized repository root |
| Activate/deactivate | A lifecycle controller's verified binding and routing state for that exact session |
| Send/receive | Controller delivery to the bound session through Pi's real input lifecycle |

The last three mappings describe the required managed adapter contract in [initialization](agents/initialization.md). The current command implements configuration preparation, not that lifecycle. Running `pi` directly with a prepared directory starts an ordinary Pi session. It must not claim workflow Coder readiness or receive Router work merely because its instructions name the role.

From the repository checkout, `./ai-fleas` offers an interactive profile → workflow → platform → project choice. The explicit form is `./ai-fleas --profile ID --workflow dev --project ID --platform pi-cli`. Its Pi path runs `pi-agents check` and `prepare`, then opens the prepared Dev Coder session. The launcher's platform choice applies to that invocation; it does not rewrite workflow YAML or turn the session into a managed agent. Other platform launch paths are pending.

The launcher offers valid profiles from this repository's public `ai-profile/` catalog, the optional sibling `../ai-fleas-platform/ai-profile/` catalog, and an optional home pointer at `~/.config/ai-fleas/config-bundle-root`. An absent private sibling is silently skipped. Interactive duplicate IDs are labeled by source; noninteractive duplicate IDs require an explicit source. `--config-bundle-root PATH` or `AI_CONFIG_BUNDLE_ROOT` exclusively selects one catalog or profile bundle. Discovery does not grant identity or workflow authority. The selected profile must register `pi-cli` as available and `pi-agents` as a command for the selected Dev workflow.

The same portable [Dev roster](../../ai-workflows/dev/agents.yml) applies regardless of platform. Selecting `pi-cli` in a work profile is a prerequisite for managed Pi agents; it does not by itself initialize the roster. The current Pi adapter covers one Dev Coder's configuration. Full Dev roster creation, communication, scheduling, continuity, independent review, and human gates remain unsupported until each required capability has a concrete implementation and verification path. A missing capability blocks the dependent workflow stage instead of merging roles into one Pi session.
