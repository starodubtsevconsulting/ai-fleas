# GPT initialization incident lessons

This note records failure modes found while repairing Admin-only and Personal Governor initialization. It is an engineering checklist, not a substitute for the exact lifecycle contracts in [`agents/admin-only-initialization.md`](agents/admin-only-initialization.md) and [`agents/personal-governor-initialization.md`](agents/personal-governor-initialization.md).

| Symptom or discovery | Boundary and lesson |
| --- | --- |
| Admin INIT was accepted, then `thread/name/set` failed against an empty rollout and the controller exited before readiness. | A chat title is presentation metadata, not identity or readiness. Keep the audit handler and readiness monitor alive after accepted INIT; retry naming only within a bounded, classified window and report title, readiness, release, and attachment independently. Never replace the task or resend an accepted or uncertain INIT merely to fix its title. |
| A newly created projectless Governor task was absent from `thread/list` before its first turn. | A blank loaded thread need not yet have a stored rollout. Permit one INIT only when the original creation connection corroborates the exact blank, projectless task through `thread/start`, `thread/loaded/list`, and `thread/read`; consume that in-memory permit once. Durable catalog evidence is still required for readiness and later reuse. |
| A generated queue bundle registered a pending binding, then invoked its inlined CLI registration path and rejected its own receipt as a duplicate. | Bundling can change module/CLI entry-point behavior. Test the generated artifact, not only private source, and ensure an imported helper cannot execute its command-line side effects. |
| Queue transport failure could erase a pending receipt even when INIT acceptance was uncertain. | Persist exact request evidence before dispatch. Retain the receipt on ambiguous failure; only a proven pre-execution rejection can justify rollback. Do not infer non-delivery from a timeout or nonzero wrapper result, and do not automatically queue again. |
| A desktop JSON-RPC reply of exactly 127 bytes used a malformed WebSocket length encoding. | Compatibility handling must recognize only the observed, valid JSON-RPC text-reply shape; retain normal frame-size, masking, opcode, and fragmentation validation. Exercise byte-boundary and malformed-frame tests. |
| Activation reached readiness, but the separate welcome turn failed or could not acquire a writer. | Activation readiness and welcome completion are separate receipts. Reconcile the exact active task and resume only an uncompleted welcome when safe; do not re-activate or create a replacement. A foreign session writer is a host-ownership condition, not evidence that the task is dead. Never advise closing a chat tab to release the writer: that action may archive the task. |
| Archiving a Governor made its active-looking receipt unusable; a new launch needed a successor. | Archive is terminal for Governor identity. Reconcile the exact archived host task, preserve its history, and create a fresh projectless successor only through the authorized lifecycle. Never unarchive or retry INIT on the archived task. |
| A ready, pinned Governor did not immediately appear in one sidebar view. | Verify host catalog, binding, completed turns, and pin state separately from UI presentation. Navigate to the exact verified chat if needed; a stale sidebar is not proof of missing readiness and must not trigger another INIT. |

Regression evidence should cover accepted and uncertain INIT, title failure, audit-handler lifetime, blank-thread catalog timing, queue receipt retention, generated-bundle entry points, WebSocket length boundaries, welcome recovery, archive replacement, and reuse without duplicate task creation or delivery. A passing unit suite does not prove installed-plugin behavior: rebuild and check the generated package, refresh the installed snapshot when authorized, then inspect the host's exact task and turn evidence.

The live Governor path was verified for readiness, completed welcome, same-task reuse after restart, and fresh successor creation after archiving. The Admin title-race and release/attachment path has deterministic coverage, but its separate live initialization test has **not** been verified; do not report Admin readiness, release, or attachment from the Governor result.
