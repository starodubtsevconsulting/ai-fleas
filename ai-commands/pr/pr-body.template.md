# PR Body Template

Use this structure by default when creating a PR body. Keep it concise, but make the intent, review surface, and
validation clear enough for a reviewer who has not followed the chat/session.

## Summary

- `<one-line outcome>`
- `<one-line behavior or workflow change>`

## Why

- `<problem / user need / operational gap>`
- `<why this belongs in this repo or workflow>`

## What Changed

- `<main code/doc/config change>`
- `<workflow or command mapping change>`
- `<docs / templates / follow-up behavior>`

## How To Use / Review

- `<command or user-facing workflow>`
- `<important files or sections to review>`

## Validation

- `<build/test/lint/command run>`
- `<manual/browser/smoke validation when relevant>`

## Follow-ups / Caveats

- `<optional caveat, TODO, or not-applicable note>`
